Mudança atômica nos dois arquivos — o HTML perde o chrome no mesmo passo em que o JavaScript passa a
gerá-lo, para que a página nunca fique sem barra superior.

**Em `predial/index.html`:**

Remover do contêiner de aplicação o bloco da barra superior inteiro e o bloco da faixa de abas
inteiro, deixando lá dentro **apenas** o bloco do miolo já existente, com o contêiner de alerta de
carga e as seis divisões de view (painel, locais, inspeções, checklist, templates, laudos), com todos
os ids exatamente como estão e com a de painel nascendo marcada como ativa.

Não tocar em mais nada do arquivo: os quatro modais continuam onde estão, irmãos do contêiner de
aplicação; a folha comum continua sendo carregada; o bloco de estilo local continua com a cor de
destaque do módulo e nada além disso; o bloco de script que importa o app continua igual.

**Em `predial/app.js`:**

Acrescentar `aplicarShell` ao bloco de imports do topo, apontando para o shell em `shared/`, no mesmo
estilo dos quatro imports já presentes.

Dentro de `boot()`, chamar `aplicarShell` **logo depois** da chamada que expõe as funções no objeto
global e **antes** do registro de fechamento de modal por clique fora. Essa ordem importa por dois
motivos: os handlers inline gerados pelo shell chamam nomes globais que precisam já existir, e o
rodapé precisa estar no DOM antes de qualquer coisa que percorra os filhos do contêiner.

A chamada passa: o nome do módulo (`Predial`), a mesma cor de destaque que o bloco de estilo do HTML
declara — os dois valores precisam ser idênticos, o do CSS evita o piscar antes de o JavaScript rodar
e o do shell é a fonte que o resto da fase padroniza —, a versão que o portal já exibe para o módulo,
e a lista das seis abas na mesma ordem, com os mesmos rótulos e emojis que estavam no HTML: painel,
locais, inspeções, checklist, templates e laudos, com a primeira marcada como ativa. O identificador
de cada item é o mesmo sufixo que a chamada de troca de view usava no HTML, para casar com os ids das
divisões de view.

Restrições inegociáveis: nenhuma função de domínio é alterada; nenhum id existente é removido ou
renomeado; a lista de nomes publicados no objeto global não muda; o Predial não passa a definir
paleta própria.
