## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Configuração do módulo → HTML do shell | Nome, rótulos de aba e versão são interpolados e injetados no DOM pelo shell comum |
| Navegador → PostgREST (Supabase) | A anon key é pública por design; a autorização real é RLS no Postgres e não muda nesta fase |
| Motor comum → dois módulos em produção | Uma regressão aqui derruba `/eletrica` e `/fonoclama` ao mesmo tempo |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05 | Denial of Service | `montarLayout()` refatorada deixando de gerar alguma das seis views, quebrando a troca de aba | medium | mitigate | Gate automatizado confere os seis ids de view e a contagem de seis itens de navegação (Task 1); verificação humana exercita as seis abas (Task 2) |
| T-05-06 | Tampering | Interpolação de nome e rótulos no shell comum atingindo dois módulos de uma vez | medium | mitigate | O escape é responsabilidade de `montarShell()`, já coberto por teste automatizado no plano 05-01; este plano só passa dados de configuração fixos no código |
| T-05-07 | Information Disclosure | E-mail interno de cargo aparecendo na tela de login após a mudança de layout | medium | mitigate | Nenhuma alteração no fluxo de login; verificação humana da Task 2 exige confirmação explícita de que nenhum e-mail aparece |
| T-05-08 | Elevation of Privilege | Perda de checagem de escrita por cargo ao mexer no motor | high | mitigate | O plano proíbe tocar em qualquer função de permissão ou renderização de domínio; a refatoração é confinada a `montarLayout()`; RLS no Postgres, que é a barreira real, não é alterada (nenhuma migração SQL nesta fase) |
| T-05-SC | Tampering | Cadeia de suprimentos de pacotes | low | accept | Nenhum pacote instalado — projeto zero-build, sem `package.json`; ver `05-RESEARCH.md` §"Package Legitimacy Audit" |
