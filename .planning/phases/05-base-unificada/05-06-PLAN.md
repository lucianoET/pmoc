<objective>
Trazer o módulo **Máquinas** para a base unificada. É o único dos seis que falha nos três critérios
ao mesmo tempo: define paleta própria, duplica o fluxo de login inteiro inline e escreve o chrome à
mão — e é também o único carregado como script clássico, o que transforma a migração para o login
compartilhado num risco não óbvio (PLAT-01, PLAT-02, PLAT-03, PLAT-16).

Por isso ele vem por último, quando o padrão já está provado nos outros cinco módulos.

**A armadilha central desta fase está aqui.** `maquinas/index.html` carrega `maquinas/app.js` como
script clássico. Nesse modo, toda função declarada no nível superior do arquivo vira automaticamente
propriedade do objeto global, que é exatamente por que os handlers inline funcionam. Importar o login
compartilhado obriga a carregar o arquivo como módulo ES, e módulo ES tem escopo próprio: **todas** as
funções somem do objeto global de uma vez. O app continua abrindo, a tela continua desenhando, e cada
botão vira erro de referência descoberto só quando alguém clica naquele botão específico. A solução
já existe no projeto e é usada pelos outros cinco módulos — um bloco explícito que publica os nomes —
e este plano a exige com gate automatizado que deriva a lista dos handlers reais do código, em vez de
confiar numa lista escrita à mão.

Purpose: sem este plano, três dos cinco critérios de sucesso da fase ficam falsos, porque um dos seis
módulos continua fora da base.
Output: `/maquinas` sem paleta própria, sem login duplicado e com o chrome vindo do shell comum.
</objective>
