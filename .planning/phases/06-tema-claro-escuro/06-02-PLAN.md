Criar `shared/tema.js` como módulo ES, com cabeçalho em caixa de linhas duplas no padrão de
`shared/shell.js`, explicando em português: que é a implementação única de tema das 7 superfícies do

**Restrição estrutural que vale para o arquivo inteiro:** nada é executado no escopo de topo além de
declarar constantes literais e funções. Nenhuma leitura de `localStorage`, nenhuma chamada de
`matchMedia`, nenhum acesso a `document` fora do corpo de uma função. Essa não é uma preferência de
estilo: `shared/shell.js` vai importar este arquivo, e `tests/shell.test.js` importa `shared/shell.js`
dentro do Node — qualquer acesso a API de navegador no momento do import quebraria seis testes que hoje
passam.

**Constantes exportadas.** `CHAVE_TEMA` com o texto `pmoc-tema` (D-03, com hífen, não sublinhado) e
`TEMAS` como lista fechada contendo `claro` e `escuro`, nessa ordem. Ambas exportadas porque o teste de
superfícies do plano 06-03 vai comparar o texto da chave com o que está escrito nos `<head>` das 7
páginas — a chave precisa ter uma fonte única de verdade também para quem confere.

**Constante interna `CORES_BARRA`,** mapeando cada tema à cor que a meta tag de cor de barra do navegador
deve receber: para `escuro`, o mesmo valor que já está hardcoded nas 7 páginas hoje; para `claro`, o valor
de `--bg` do bloco de tema claro que o plano 06-01 fixou em `shared/pmoc.css`. Não exportar.

**`normalizarTema(valor)` — pura, o filtro de segurança do arquivo.** Recebe qualquer coisa e devolve o
texto do tema apenas se o valor for **estritamente idêntico** a um dos itens de `TEMAS`; para tudo o mais
devolve nulo. Sem `trim`, sem conversão de caixa, sem conversão para texto: comparação estrita contra
lista fechada. Comentar em português por que a comparação é estrita — o valor vem de `localStorage`, que
é gravável por extensão de navegador, pelo console do usuário ou por um erro de uma versão futura do
próprio código, e a única postura defensável é tratá-lo como não confiável e recusar o que não for
exatamente um dos dois textos previstos (ASVS V5).

**`proximoTema(atual)` — pura.** Devolve o outro tema: dado `claro` devolve `escuro`; dado qualquer outra
coisa, inclusive valor não reconhecido, devolve `claro`. Comentar que a queda para `claro` é deliberada:
a função só é chamada com o tema atualmente aplicado no documento, e se esse valor estiver corrompido a
alternância mais útil ao usuário é ir para o tema que ele ainda não tem.

**`detectarTema()` — lê preferência, não escreve nada.** Tenta ler `CHAVE_TEMA` de `localStorage` dentro
de um `try`/`catch` (armazenamento pode estar bloqueado por política do navegador, e nesse caso o acesso
lança em vez de devolver nulo). Passa o valor lido por `normalizarTema`; se sobreviver, devolve. Caso
contrário consulta a preferência do sistema, e só se `matchMedia` existir no escopo global — navegador
antigo sem essa API não pode derrubar a página: devolve `claro` quando a consulta
`(prefers-color-scheme: light)` casar, e `escuro` em qualquer outro caso, inclusive quando a API não
existe. Escuro é o padrão histórico do projeto e continua sendo o padrão quando não há informação.

**`temaAtual()`** devolve o tema em vigor no documento, lendo o atributo `data-theme` do elemento raiz e
passando por `normalizarTema`, com queda para `escuro` se o atributo estiver ausente ou inválido.

**`aplicarTema(tema)` — o único ponto que escreve no documento.** Normaliza a entrada, caindo para
`escuro` se não reconhecer. Escreve o atributo `data-theme` no elemento raiz do documento com o texto do
tema. Localiza a meta tag de cor de barra do navegador pelo seletor de atributo de nome e, **se ela
existir**, atualiza o conteúdo dela com a cor correspondente em `CORES_BARRA`. Localiza o botão de tema
pelo id `btn-tema` e, **se ele existir**, sincroniza o rótulo e o texto acessível: quando o tema em vigor
é `escuro` o botão oferece ir para o claro, e quando é `claro` oferece ir para o escuro — o rótulo é um
glifo de texto simples (sol para "ir para o claro", lua para "ir para o escuro"), e tanto o atributo de
título quanto o rótulo acessível recebem a frase em português correspondente. Devolve o tema aplicado.
Todos os três alvos são opcionais de propósito: `aplicarTema` precisa funcionar no portal, onde a meta
tag existe mas o botão pode ainda não ter sido montado, e em qualquer página futura que não tenha um dos
dois.

**`alternarTema()` — a função que o botão chama.** Calcula `proximoTema(temaAtual())`, tenta gravar o
resultado em `localStorage` sob `CHAVE_TEMA` dentro de um `try`/`catch` (armazenamento bloqueado não pode
impedir a troca dentro da sessão), aplica o tema e devolve o texto do tema novo. Não recarrega a página,
não redesenha nenhuma view, não dispara nenhum evento: trocar um atributo do elemento raiz basta, porque
todo o visual sai de variáveis CSS.

**`iniciarTema()` — chamada uma vez no boot de cada superfície.** Aplica `detectarTema()` e expõe
`alternarTema` no escopo global sob o nome `alternarTema`, para que o manipulador embutido do botão
funcione — é exatamente o mesmo padrão que `onclick="sair()"` já usa hoje na barra superior e que a
função `exporNoWindow()` de cada módulo estabeleceu. Devolve o tema aplicado. Deve tolerar ser chamada
mais de uma vez sem efeito colateral: ela é idempotente por construção, já que só reescreve o mesmo
atributo e a mesma referência global.

**Não registrar** nenhuma escuta de mudança de `prefers-color-scheme` em tempo de execução. A preferência
do sistema serve como valor inicial quando não há escolha salva; depois que o usuário clicou no botão, a
escolha dele prevalece, e uma escuta ativa a sobrescreveria — quebrando o critério de sucesso 3.

Sem `import` de nada. Sem dependência externa. Sem framework.
