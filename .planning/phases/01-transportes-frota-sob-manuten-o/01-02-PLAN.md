## Phase Goal

**As a** gestor ou técnico do CMASM, **I want to** controlar a manutenção por uso (km ou horas de
motor) de viaturas e embarcações no módulo publicado em `/transportes`, **so that** eu saiba o que
está vencido e o que está prestes a vencer sem depender de controle manual em planilha.

> ⚠ Ver nota sobre o formato da user story em `01-01-PLAN.md` — a linha `**Goal:**` do ROADMAP ainda
> não está no formato canônico. Rode `/gsd mvp-phase 1` para tornar a história canônica na fonte.

<objective>
Entregar a fatia vertical do **estoque de peças do módulo Transportes**: o gestor cadastra peças com
estoque mínimo e preço, registra entradas e saídas manuais, e passa a ver quais peças estão abaixo do
mínimo (TRANSP-07, parte de cadastro e alerta).

Hoje não existe nenhuma tabela de material no módulo — `transp_materiais`, `transp_plano_materiais` e
`transp_estoque_movimentos` são criadas aqui, com estoque próprio do módulo e prefixo próprio, sem
compartilhar tabela com o módulo de máquinas (D-06).

A migração deste plano também acrescenta a `transp_manutencoes` as três colunas que transformam o
registro simples de manutenção em OS (`plano_id`, `status`, `custo_pecas`). Isso é feito aqui, e não
num quarto arquivo de migração, por uma razão operacional explícita: cada migração exige uma aplicação
manual no SQL Editor, e concentrar as duas mudanças aditivas restantes em um único script reduz de
três para dois o número de intervenções no banco de produção. As colunas são consumidas pelo Plano
01-03.

Purpose: sem peças cadastradas e sem saldo, a baixa automática de estoque da OS (TRANSP-03) e a lista
de compras (TRANSP-07) não têm o que movimentar.
Output: migração `supabase/23_transportes_estoque_os.sql` aplicada e aba "Estoque" funcional com
alerta de estoque mínimo.
</objective>

Criar `supabase/23_transportes_estoque_os.sql`, estritamente aditivo, com o mesmo cabeçalho em caixa
de linhas `═` usado nas migrações anteriores do módulo.

Nota sobre o critério de aceite que conta zero ocorrências de definição da função de RBAC: o nome da
função **deve** aparecer neste script (as policies a invocam), mas **não** pode aparecer precedido de
uma instrução de criação — ela já foi definida na migração 22 e redefini-la aqui sobrescreveria o
objeto em produção.

**1. `transp_materiais`** (`create table if not exists`): `id bigint generated always as identity
primary key`; `codigo text unique`; `nome text not null`; `tipo text not null default 'consumivel'`
com restrição aos valores `consumivel` e `peca`; `unidade text not null default 'un'`; `preco numeric
check (preco is null or preco >= 0)`; `estoque_atual numeric not null default 0 check (estoque_atual
>= 0)`; `estoque_minimo numeric not null default 0 check (estoque_minimo >= 0)`; `obs text`; `ativo
boolean not null default true`. As duas restrições de não negatividade são obrigatórias — são a única
barreira contra saldo negativo já que a baixa é calculada no cliente (Pitfall 5 da pesquisa).

**2. `transp_plano_materiais`**: `id bigint generated always as identity primary key`; `plano_id
bigint references transp_planos(id) on delete cascade`; `material_id bigint references
transp_materiais(id) on delete cascade`; `quantidade numeric not null default 1 check (quantidade >
0)`; `unique (plano_id, material_id)`.

**3. `transp_estoque_movimentos`**: `id uuid primary key default gen_random_uuid()`; `material_id
bigint references transp_materiais(id)`; `manutencao_id uuid references transp_manutencoes(id)`;
`tipo text not null` restrito aos valores `entrada` e `saida`; `quantidade numeric not null check
(quantidade > 0)`; `motivo text`; `registrado_em timestamptz default now()`. A referência a
`manutencao_id` é o que torna possível detectar baixa já efetuada e evitar duplicação no Plano 01-03.

**4. Colunas novas em `transp_manutencoes`**, cada uma com adição condicional (`add column if not
exists`), para permitir reexecução idempotente do script (Pitfall 3 da pesquisa):
`plano_id bigint references transp_planos(id)`; `status text not null default 'concluida'` restrito
aos valores `pendente`, `em_andamento`, `concluida`, `cancelada` — o valor padrão preserva a
semântica das linhas já existentes, que representam manutenções já realizadas; `custo_pecas numeric
default 0`. Nenhuma coluna existente é redefinida e nenhuma linha é apagada.

**5. Índices** (todos com `if not exists`), cobrindo cada chave estrangeira criada, conforme a regra
do skill de Postgres do projeto: `transp_plano_materiais_plano_id_idx`,
`transp_plano_materiais_material_id_idx`, `transp_estoque_movimentos_material_id_idx`,
`transp_estoque_movimentos_manutencao_id_idx` e `transp_manutencoes_plano_id_idx`.

**6. Grants**: `select` para `anon` e `authenticated` nas três tabelas novas; `insert, update, delete`
apenas para `authenticated`. Incluir `grant usage, select on sequence` para
`transp_materiais_id_seq` e `transp_plano_materiais_id_seq` — sem isso o insert falha com erro de
permissão de sequence (Pitfall 4). `transp_estoque_movimentos` usa `uuid` e não precisa de sequence.

**7. RLS**: habilitar row level security nas três tabelas novas e criar, para cada uma, as quatro
policies prefixadas (`sel_`, `ins_`, `upd_`, `del_` seguidos do nome da tabela), no mesmo formato do
Plano 01-01: leitura com condição constante verdadeira (preserva leitura do observador e do painel) e
as três operações de escrita restritas a `authenticated` avaliando `transp_pode_escrever()` envolvida
em subquery. Preceder cada `create policy` de um `drop policy if exists` de mesmo nome. **Não
redefinir** `transp_pode_escrever()` — ela já existe desde a migração 22.

**Decisão registrada:** as policies já existentes de `transp_manutencoes` (criadas na migração 10, sem
distinção de cargo) **não são alteradas** por este script, conforme a recomendação da pesquisa de só
aplicar o RBAC novo às tabelas novas. O risco residual está registrado como T-02-05 no modelo de
ameaças deste plano.

Restrições inegociáveis: o script não remove tabelas nem colunas; não referencia objeto algum dos
módulos Refrigeração ou Máquinas; todo objeto novo tem nome prefixado por `transp_`.
